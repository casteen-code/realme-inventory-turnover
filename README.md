# realme 库存周转管理

把三个仓库的现有库存，与 Shopee 五家分店和 TikTok Shop 的上周销量放在一起，识别商品规格，计算还能卖多少天。

[打开工具](https://casteen-code.github.io/realme-inventory-turnover/) · [查看代码](https://github.com/casteen-code/realme-inventory-turnover) · [使用虚构示例](examples/README.md) · [Casper 作品集](https://casteen-code.github.io/Personal-portfolio-website/)

## 这个项目解决什么问题

同一款手机在仓库、Shopee 和 TikTok 报表里可能写成不同名称，内存顺序、颜色拼写、汇总行也不一致。直接拼接报表容易漏掉 SKU，或把“店铺合计”当成商品，影响补货判断。

这是面向电商运营和库存负责人制作的浏览器工具。项目由 Casper 根据实际工作流程提出需求、定义仓库和店铺关系、验收结果，并使用 AI 辅助开发与迭代。这里展示的是业务问题梳理、数据规则设计和工具落地过程，不以代码行数或未经验证的增长数字作为成果。

## 已实现的功能

- 点击或拖入 `.xlsx`、`.xls`、`.csv`；查看识别的工作表、字段、行数和数量。
- 统一 realme 手机的型号、内存和颜色写法，区分 `16`、`16 Pro`、`16 Pro+` 等不同型号。
- 检查库存识别完整性；自动排除总计、合计、小计和已配置的赠品 SKU `zp888`。
- 自动匹配有足够依据的销售 SKU；有歧义的项目保留人工处理，支持记住、撤销及备份匹配规则。
- 同时提供“型号汇总”和“完整 SKU”两张周转表，显示各店销量、总销量和周转天数。
- 按全部仓库或单仓查看，按周转、库存、销量或名称排序，导出当前表 CSV。
- 本机保存最近 30 次计算结果快照，便于回看和导出。

## 计算口径

**周转天数 = 当前可用库存 ÷（上周销量 ÷ 7）。**

例如库存 30 台、上周销售 10 台，日均销量约 1.43 台，周转为 21 天。这里计算的是按上周销售速度估算的库存可售天数，不是财务口径的“库存周转率”。上周无销量时显示“无销量”，不把它当成 0 天。

| 仓库 | 对应销量 |
| --- | --- |
| 巴厘岛（Bali） | Shopee 1 店、3 店、TikTok Shop |
| 坤甸（PNK） | Shopee 4 店 |
| 马卡萨（MKS） | Shopee 2 店、5 店 |

型号汇总会合并同型号的内存和颜色。完整 SKU 表保留型号、内存、颜色三个维度。不同型号不合并；整体验证使用库存合计和销量合计重新计算，不平均各行周转天数。

使用前请自行确认销售文件属于同一个完整的 7 天周期、库存是对应时点的快照。当前工具不会自动检查报表的实际起止日期，负库存按 0 处理。

## 四步使用

1. 打开工具，将三份仓库库存、Shopee 分店销量和 TikTok SKU 销量分别放进对应的五个框。
2. 查看导入预览，确认工作表、识别字段和数量正确。如果 Shopee 同时含明细和汇总且对不上，选择实际采用的来源，不会把两份销量相加。
3. 生成周转表，检查库存识别异常及销售待确认项，必要时修正 SKU 或手动对应。
4. 切换型号 / 完整 SKU、仓库范围和排序；导出 CSV。重复工作可使用已记住的规则及历史结果。

第一次体验请使用 [五份虚构 CSV 示例](examples/README.md)，不要用真实经营文件制作公开截图。

## 数据保存在什么地方

报表在当前浏览器读取和计算，没有报表上传接口、账户系统或云端同步。应用和 Excel 读取组件都随网站提供，不依赖外部脚本 CDN。打开网页仍会向静态托管服务请求网页文件。

匹配规则和历史快照保存在浏览器本地。更换设备、换浏览器、使用无痕模式或清除网站数据，可能无法找到之前的记录。任何能使用同一浏览器资料的人也可能看到这些本地结果。

- 规则备份：在“SKU 规则中心”导出 JSON，恢复时导入该文件。规则文件可能含商品信息，请不要提交到公开仓库。
- 结果备份：分别导出需要保留的型号 / SKU 结果 CSV，并自行保存原始库存和销售报表。
- 当前**没有完整历史数据库的一键导出和恢复**。历史是结果快照，不是原始文件备份，不能当作云端存档。

## 已知边界

- 识别规则围绕 realme 报表建立，不是通用的全品牌识别模型，也不是在线 AI 服务。
- 缺少关键字段、真实缺货、新型号或颜色存在歧义时，仍需核对，不会为了消除异常强行合并。
- 三个库存文件和两个销售文件均需有有效字段；没有销量时也应提供格式完整的零销量表。
- 本工具反映输入文件和已确认规则的结果，不能替代仓库实盘与源系统对账。
- 公开仓库只包含代码、测试和明确标注的虚构示例，不应提交客户、订单、真实库存、销售文件、密码或密钥。

## 本地运行与部署

下载本仓库后，保持文件结构不变，直接打开 `inventory-turnover.html` 即可使用，不需要安装应用服务器。浏览器对本地文件的数据保存行为可能不同，固定的 HTTPS 入口更适合长期使用。

维护者使用 Node.js 22 或更新版本，运行：

```sh
npm run verify
```

无需安装第三方构建依赖。验证包含 21 个 SKU 案例、导入与匹配回归、示例控制数、两种网页入口、静态资源和发布白名单。原有解析与计算代码保持 v3.4.3，不因拆仓库而改动业务算法。

GitHub Pages 只使用 `.github/workflows/pages.yml`：

1. 在仓库 **Settings → Pages → Source** 选择 **GitHub Actions**，不要再启用 `main / root` 分支直接发布。
2. 合并经验证的更改到 `main`。检查通过后，仅发布 `dist/client` 的明确文件清单。
3. 确认 Actions 部署成功，并实测首页、兼容入口和示例。`deployment.json` 可核对线上版本、提交和文件摘要。

该仓库只发布库存工具，不发布 TikTok 经营看板或活动背景工坊。每天更新其他工具的数据不会触发这里的部署。仓库及主页公开可访问不等于已授予所有代码和商标的通用开源许可；第三方组件说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 迁移与恢复

新主入口为 `https://casteen-code.github.io/realme-inventory-turnover/`，同仓兼容入口为 `inventory-turnover.html`。原混合仓库旧入口应保留迁移跳转，避免同事收藏的链接失效。

拆分保留 `realme-turnover-stable-v1` 数据库、原有表结构及 `turnover.v3.*` 后备存储键。在相同的 `https://casteen-code.github.io` 域名、同一个浏览器资料下，仅切换仓库路径仍可访问原有本地存储。换域名、从 `file://` 切到 HTTPS 或浏览器已经清理数据时不适用；建议先备份规则和结果。

代码恢复：找到最后验证成功的提交，用新的撤销提交恢复有问题的更改，再让同一个发布流程重新发布。不要强制覆盖历史，也不要重新启用第二套发布方式。恢复代码不会自动找回已被清除的浏览器数据。
